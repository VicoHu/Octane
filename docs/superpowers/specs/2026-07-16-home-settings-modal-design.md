# Home 设置弹窗视觉匹配设计

## 背景

Home 页设置弹窗当前尺寸偏小、内容密度过高，字号和留白与主页的宽松内容区、清晰卡片层级不一致。本次调整依据 `DESIGN.md`，让设置弹窗与 Home 页形成同一套视觉语言。

## 目标

- 提升设置内容的可读性，避免分类导航、子标签和正文挤在狭小区域。
- 复用 Home 页的选中态、间距、圆角、边框和品牌色使用方式。
- 保留设置弹窗的轻量交互，不改造成独立设置页。
- 不改变现有设置分类、业务逻辑、数据流和错误处理。

## 布局

采用宽幅双栏弹窗：

- 弹窗使用 `width: min(920px, calc(100vw - 64px))` 和 `height: min(640px, calc(100vh - 64px))`；较窄桌面视口不得产生页面横向滚动。
- 顶部为独立标题区，包含“系统设置”、简短说明和关闭按钮。
- 标题区下方为双栏结构：左侧约 `200px` 的分类导航，右侧为可滚动的设置内容区。
- 右侧内容区使用 `24–32px` 内边距；内容超出时只滚动内容区，标题和分类导航保持稳定。

## 视觉层级

- Modal 使用 `16px` 圆角、语义边框和 `DESIGN.md` 的 elevated 阴影。
- 标题使用 `title-sm`（`20px`）；内容主阅读文字使用 `body-lg`（`16px`）；导航和辅助文字使用 `body`（`14px`）。
- 分类选中态与 Home 侧栏一致：`3px` 品牌绿竖条、中性浅底和加重文字；hover 只使用中性底色。
- 每个设置内容区最多保留一个绿色主焦点。主按钮使用品牌绿底和炭灰前景；次操作使用 outline 或 ghost。
- 子分类继续使用现有 `Tabs`，通过更充足的间距与标准 `40px` 控件高度改善密度。
- 不增加装饰性色块、渐变或重阴影，不在 Modal 内引入无必要的嵌套卡片。

## 组件边界

- `SettingsModal` 负责弹窗外壳、标题、分类导航和内容区布局。
- `ShortcutsSection`、`BackupSyncTabs`、`FaviconCacheSection`、`PasswordSection`、`EncryptionTtlSection` 保持现有职责和行为。
- 优先复用现有 shadcn/ui `Dialog`、`Tabs`、`Button` 等组件，只在 `SettingsModal` 的局部 CSS Module 中定义布局。
- 不修改全局主题 token；所有视觉值映射到 `DESIGN.md` 已有语义 token。

## 交互与可访问性

- 保持 Dialog 的 Escape、遮罩关闭和焦点管理行为。
- 分类使用可键盘操作的 vertical Tabs，并保留明确的 `aria-label`。
- 关闭按钮保留可访问名称和可见焦点态。
- 内容区滚动时，不隐藏当前分类或弹窗标题。

## 测试与验收

- 先添加设置弹窗结构测试，覆盖标题、说明、四个分类和分类切换后的真实内容渲染。
- 按 `docs/standards/testing.md` 使用真实 UI 组件、`userEvent` 和语义查询。
- 执行定向测试、完整测试和类型检查。
- 在实际浏览器中检查至少 `1440 × 900` 和较窄桌面视口，确认无横向滚动、文字不重叠、内容区滚动正常。
- 截图对照 Home 页，确认圆角、边框、绿色焦点、选中条、字号和留白一致。

## 非目标

- 不新增设置项。
- 不修改备份、同步、密码或缓存逻辑。
- 不重构各设置 section。
- 不调整 Home 页其他区域或全局组件尺寸。
