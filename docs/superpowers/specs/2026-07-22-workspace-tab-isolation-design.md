## Problem Statement(问题陈述)

Octane 已有「工作区」概念,但工作区之间的浏览器标签页没有隔离——在 A 工作区打开的 tab 切到 B 后仍在,tab 随工作区切换**线性膨胀**。

根因:`selectWorkspace`(src/store/useWorkspace.ts:128)切换只改 `currentWorkspaceId` + 写 storage.local,**完全不碰浏览器 tab**;`useOpenTabs` 是纯内存只读镜像不落盘——项目零浏览器 tab 持久化。

用户诉求:① 切换时隔离(关闭或隐藏,不绝对);② 保存当前 tab 状态(含顺序),切回恢复;③ 用户选项(关闭 vs 隐藏);④ 切回恢复上次状态。

## Constraints(硬约束,不可绕开)

| C5 | MV3 SW ~30s 回收 | 切换编排跑 home 页(非 SW);仅 v1.1 自动归档跑 SW |

## Premises(前提)

1. "隐藏"在 MV3 做不到字面意义;v1 只交付 close,hide 推 v1.1。
2. 关闭模式只恢复 URL 集合,不保留页面运行时态——天花板,须诚实。
3. 会话追踪用「窗口绑定」:窗口绑某 ws,窗内 tab 即属之。多窗口天然独立;同 ws 多窗归档合并是已知限制(P5)。
4. 默认 off,显式开启;首启存量 tab 告知 Modal。
5. v1 单窗口为主;同 ws 多窗 = 最后归档胜出(v1.2 合并)。

## v1 范围(rev4 收紧)

**close-only + 手动切换**。**v1 设置 UI 不展示 hide 选项**(rev4 #12:避免"可选但无实现"矛盾;v1.1 加 hide 时再露)。自动归档、hide、lazy restore、多窗口同 ws 合并 → 全部 v1.1+。

## Approaches Considered

- **A 会话感知归档/恢复 + 强度开关** ✅ 选定(v1 收紧到 close-only)。
- B 无状态 URL 匹配 + 仅关闭 — 被否(归属模糊)。

## 核心数据模型(rev4:storage.local + 瘦身)

**TabEntry**(rev4 砍 title/favIconUrl/activeUrl —— tabs.create 自动重取 title/favicon;active 在切换入口是 home tab 取不到):
```ts
interface TabEntry { url: string; pinned?: boolean; order: number; }
interface TabSession { tabs: TabEntry[]; savedAt: number; }
```

**存储键(rev4 全部 chrome.storage.local,分键避 RMW 竞态)**:
```
tabSession.<workspaceId>          → TabSession        // per-workspace 会话(分键)
windowWorkspaceBinding.<windowId> → workspaceId       // per-window 绑定(分键,非单 map)
tabIsolationSetting               → { mode:'off'|'close' }   // v1 只有 off/close
```
> rev4 #7:binding 用 `windowWorkspaceBinding.<windowId>` 分键(非 `{[windowId]:wsId}` 单 map),多 home 实例并发不互相覆盖。`windows.onRemoved` 清理对应 binding key。

## 切换编排(rev4 硬化:单命令 + 串行队列 + archive 硬屏障)

**单命令**(rev4 #13):AppRail 和 Sidebar **共用** `requestWorkspaceSwitch(toId, windowId)`,不各自拼装。`selectWorkspace` 保持纯 UI(zustand + persist),create/delete 走它不编排。

```
requestWorkspaceSwitch(toId, W):                 // 唯一切换入口
  if busy[W]: queue/reject; return               // #2 per-window 串行门控(防 A→B→C 并发覆盖)
  busy[W] = true
  fromId = readBinding(W)                        // 分键读
  if fromId == null or fromId === toId: busy[W]=false; return
  try:
    1. archived = archive(W, fromId):
         tabs = chrome.tabs.query({windowId:W})  // 异常 → 抛
         restorable = tabs.filter(isRestorable)  // #10:过滤内部页 + devtools:/受限 file: 等不可恢复项
         if query/write 抛异常: Toast.error("切换中止:无法保存当前标签"); RETURN  // #1 硬屏障,不动 tab
         write tabSession.<fromId> = {tabs: restorable.map(toEntry), savedAt}
    2. disposeSet = removeContentTabs(W):         // 保 home tab
         chrome.tabs.remove(contentTabIds)        // 记录已处置 id 集;部分失败 Toast 不阻断(#3 有记录)
    3. openedIds = openTabsInWindow(W, tabSession.<toId>?.tabs ?? [], {active:false}):  // #9 + DRY helper
         chrome.tabs.create 逐条 {url,active:false,index}  // 显式 active:false 防抢焦点闪烁
    4. if openedIds.length: chrome.tabs.update(openedIds[0], {active:true})  // 单次激活首位(#9)
    5. writeBinding(W, toId)                       // 分键写 + onChanged 广播给各窗 home
    6. undo token = {fromId, disposeSet, openedIds} → Toast「已归档 N 个」+ 撤销(短窗口)
  finally: busy[W] = false
```
顺序硬约束:archive(**失败必中止,硬屏障**)→ dispose → restore → 绑定。**无原子性**,靠 per-tab 处置集 + Toast + undo 兜底。

**v1 不做 restore 去重**(rev4 #8):正常 dispose 后窗内只剩 home tab,restore 不撞车;normalizeUrl 是书签匹配规则非 tab 身份规则,语义错。仅用完整 URL 精确比较做幂等兜底(可选)。

**openTabsInWindow helper**(rev4 DRY):restore / undo-restore-A / 首启存量收纳 三处复用。

## undo(rev4 完整语义 + 短窗口)

切换 A→B 后 Toast 撤销:① dispose B 的 openedIds(本次恢复集)→ restore A(tabSession.<A>)→ 回滚 binding=A。**仅 Toast 存活期内有效**(token 在 home 内存,超时/刷新失效——业界常规)。用户在 B 新开 tab 不保护。

## 绑定生命周期(rev4:#5 深化 + #6 首次创建)

- **首次绑定**:① `loadWorkspaces` 完成后,若本窗无 binding → 用 `lastWorkspaceId`(或 first ws)回写 + set zustand;② `windows.onCreated` 给新窗默认 binding;③ **首次 createWorkspace**(零 ws → 1 ws,rev4 #6):create 后立即给当前窗 binding = 新 ws(create 本身不编排,但须补 binding)。
- **delete 深化**(rev4 #5):删 ws X 时:
  1. 扫所有 `windowWorkspaceBinding.*`,凡 =X 的窗口 → rebind 到 fallback(或删最后 ws 时 deleteBinding);
  2. 该窗内残留内容 tab **成为 fallback 的打开集**(下次切换归档进 fallback——故意,非污染;首启 Modal/undo 兜底惊讶);
  3. **删除 `tabSession.<X>`**(隐私:不留已删 ws 的 tab URL);
  4. 删最后 ws:所有 bound window deleteBinding,内容 tab 保留不归属。
- **windows.onRemoved**:清对应 binding key(rev4 #7)。

**澄清**(rev4):`lastWorkspaceId`(全局,popup 写,语义=保存目标)≠ `windowWorkspaceBinding.<W>`(per-window,语义=当前浏览工作区)。popup 改 ws 不触发 tab 隔离。home 一旦绑定后用 binding 而非 lastWorkspaceId。

## 用户设置 UX

SettingsModal 新增「**工作区与标签**」分区:隔离强度分段 `关闭(不隔离)` | `关闭`(v1 只这两档,hide 不展示)。关闭模式说明:"切换工作区会关闭当前标签并保存网址,切回时重新打开。页面滚动位置与表单输入不会保留。"

## UI/UX Design (rev 5 — /plan-design-review 锁定,Codex 主)

> **取代上方「用户设置 UX / 首次启用存量告知 / 切换后撤销 Toast」三节**(它们用的"关闭(不隔离)/关闭/归档/撤销"术语已废)。本节是 UI 权威规格。
> 核心心智模型(统一术语):**离开工作区时关闭其标签,返回时自动恢复**。`archive/dispose/restore` 只留在代码里,不暴露给用户。

所有视觉对齐 DESIGN.md:炭灰主操作(`action-primary #202829`)+ 品牌绿仅 accent(绿是图标/选中/focus,不做底色;绿底白字禁止);扁平无重阴影;圆角 8/12/16;字号 12/14/16/20/24。

### 1. 设置分区「工作区与标签」(RadioGroup)
- 外层垂直 line tabs 加第 6 项「工作区与标签」(放「关于」前);右侧 `sectionHeader`(h2「工作区与标签」+ p「控制切换工作区时如何处理已打开的标签。」)。
- **控件:shadcn `RadioGroup`(纵向两行)**——非 Tabs(Tabs=视图切换)、非自绘 segmented(重复造键盘/焦点/选中语义)。**项目未装,施工前 `pnpm dlx shadcn@latest add radio-group`。**
- 字段名「**切换行为**」(非"隔离强度",这是行为选择不是强度连续量)。两选项:
  - 「**不隔离**(默认)」— 切换工作区时,保留所有已打开的标签。
  - 「**自动关闭与恢复**」— 离开工作区时关闭其标签;返回该工作区时自动恢复。
- 选中态:绿 Radio 点 + 字重(颜色非唯一);40px 行、≥44px 触达;说明文案 `aria-describedby` 绑定;方向键切换。**不套 Card、不造绿底板。**
- 状态:Loading(RadioGroup 禁用 + 「正在读取设置…」);Success(选中态 + 短暂「已保存」行内,不弹 Toast);Error(控件回原值 + 行内错误 + 重试)。无 Empty。
- 从「不隔离」切到「自动关闭与恢复」:先弹下方确认 Dialog,确认后才更新选中。

### 2. 切换结果 Toast(Sonner action)
- 复用 `src/components/ui/toast.tsx`,**但现有 shim 缺 `action`——施工时扩展**(sonner 原生支持 action,shim 暴露即可)。
- 标题「已切换到「工作区 X」」+ 描述「已关闭 N 个标签」+ action「**切回「工作区 Y」**」(**非"撤销"**——仅重开旧 tab 破坏隔离,完整反转切换才成立)。
- N=0 不弹;persist 8–10s;`role=status` `aria-live=polite`;action 可 Tab 到达 ≥36px;绿只给成功勾图标,action 用炭灰/ghost。
- 状态:Success(如上);Error「未能切换到「X」/仍停留在「Y」」+ 重试;Partial「切换未完成:还有 N 个标签未恢复」(不伪装 success);回退成功同一 Toast 更新为「已切回「Y」」(不叠新条)。

### 3. 首启确认 Dialog(AlertDialog)
- 用 shadcn `AlertDialog`(非普通 Dialog,有后果的设置变更),但**确认键不红**(非危险删除)。仅 N>0 弹(N=0 直接开启)。
- 标题「开启标签隔离?」+ 描述「当前窗口的 N 个标签将归入「工作区 X」。离开该工作区时关闭,返回时恢复。」+ 取消 / 「开启隔离」(炭灰主键 + 可选绿 `ArchiveRestore` 图标)。
- ⚠️ `AlertDialogContent` 现用 `rounded-xl`——**施工时确认映射到 16px**(DESIGN.md Modal=rounded lg)。
- 状态:先完成 tab 计数再开 Dialog(禁 N 占位);Confirming(按钮「正在开启…」+ 禁关闭/Escape/重复提交);Error「未能开启,设置未更改」(Dialog 保持开);Partial「已处理 17/20,3 个未处理」+ 重试未处理项/暂不启用。初始焦点放「取消」。

### 4. 切换进度反馈(rev5 新增面,Codex 判 BLOCKING)
设计原漏此 UX 时刻(几十 tab 处理期间无反馈→用户重复点击/误判失败)。两层反馈:
- **立即**:触发的工作区项显 Spinner + 所有切换入口 `aria-disabled`(防重复点击)。
- **>300ms**:持久 Sonner loading Toast(**同一 toast id 更新**,不叠新条)+ 总数已知时 shadcn `Progress`。
- 文案:「正在切换到「工作区 X」」→「正在关闭当前标签 18/42」→「正在恢复「工作区 X」标签 8/21」。禁阻塞 Modal/全屏遮罩;旧 ws 内容保持可见,完成一次性切换。
- a11y:`role=progressbar` `aria-valuenow/max`;live region 最多 500ms 更新一次(不逐 tab 播报);焦点留原触发项;遵守 `prefers-reduced-motion`;绿只给 Spinner/进度线,Toast 背景白。
- 状态:Progress(阶段+计数,非模糊百分比);Success(原 Toast 原位转结果面 §2);Error「未能切换/仍停留在 Y」+ 重试;Partial 持久不消失「已关闭 42,已恢复 18/21」+ 继续切换/返回 Y。

## 关键边界

| 情况 | 处理 |
|---|---|
| pinned home tab | archive/dispose/restore 全程排除(app shell);isInternalPage + home url |
| 可恢复性过滤(rev4 #10) | 过滤 chrome:///edge:///about:/chrome-extension: + **devtools:/受限 file:** 等未证明可恢复项;不可恢复 tab 不进 dispose 集 |
| 多窗口同 ws | v1 已知限制:最后归档胜出(v1.2 合并) |
| incognito | 不纳入(无权限) |
| 并发切换(rev4 #2) | per-window busy 门控串行化 |
| archive 失败(rev4 #1) | 硬中止,不动 tab,Toast 报错 |
| 删 ws(rev4 #5) | rebind 所有 bound 窗口 + 清 tabSession.<X> + 处理最后 ws |

## NOT in scope

- hide 模式(tabGroups 折叠+discard)→ v1.1(C3 三硬伤需专门处理)。
- 自动归档(Arc 式 alarms)→ v1.1(跑 SW,复杂度独立)。
- lazy restore(占位点击载入)→ v1.x(大 session 性能优化;v1 eager + N>50 console.warn 探路)。
- 多窗口同 ws 会话合并去重 → v1.2。
- 跨设备 tab 会话备份恢复 → 不做(rev4:tab 会话设备本地临时,storage.local 不进 backup/share)。

## Success Criteria

- 切换后新 ws 窗口只显示其相关标签(无泄漏);切回按 URL 恢复(顺序/pinned)。
- 设置选 `关闭(不隔离)`/`关闭`;选不隔离时行为不变(向后兼容)。
- `pnpm run typecheck` + `pnpm run test` 双绿;新增逻辑层 + 集成测试。
- pinned home tab 任何模式不被误关/误归档。
- 切换有完整 undo;首启 close 有存量 Modal。
- **archive 失败绝不关 tab**(硬屏障回归测试);**并发切换不互相覆盖**(串行队列测试);**create/delete 不编排 + delete 正确 rebind/清 session**(回归)。
