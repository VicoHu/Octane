## Problem Statement

P1 解决了本地全量导入导出。本版本（0.1.3.5）补上**对象存储备份**：用户可把数据手动上传到阿里云 OSS / 腾讯云 COS，换设备/重装时从云端恢复。覆盖式语义（与 P1 一致），不做 diff/合并。

## Scope（本版本）

- **P2 — 云存储配置**：凭证加密存储（D2:B，复用 CryptoService）、provider 策略抽象、OSS/COS 适配、配置 UI、连通性测试、CORS/host_permissions 前置。
- **P3 — 云上传/下载**：上传备份（覆盖云端单 key）、从云恢复（复用 P1 导入事务）、上次备份时间。
- **范围决定（D4）**：OSS + COS **两家都做**，不分版本。

## Decisions

| 决策 | 选择 | 理由 |
|---|---|---|
| D1 加密数据导出形态 | 密文导出 | 伞形 spec 已定（P1 已落地） |
| D2 凭证存储 | AK/SK 经主密码 AES-GCM 加密存 chrome.storage.local | 伞形 spec 已定，本版本落地 |
| D3 云同步深度 | 手动上传/下载，覆盖式 | 伞形 spec 已定 |
| **D4 provider 范围** | **OSS + COS 都做（0.1.3.5）** | 用户决定：一步到位覆盖两家 |
| **D5 架构** | **策略模式**（`CloudStorageProvider` 接口 + OSS/COS 实现 + 注册表） | 用户决定：方便后期扩展其他服务商 |
| **D6 签名实现** | **两家都用官方 SDK**（`ali-oss` + `cos-js-sdk-v5`），**不做手写回退** | 用户决定：信任 SDK 浏览器支持 |
| **D7 上传确认门槛** | **上传 = 轻提示（非破坏性）**；**从云恢复 = 破坏性确认 Modal + Checkbox** | 用户决定；**反转伞形 spec Open Question #4**（见下） |
| D8 AK/SK 清除入口 | 提供（安全卫生） | 伞形 spec Open Question #2 结论 |

### D7 反转伞形 spec Open Question #4（显式记录）

伞形 spec Open Question #4 原写「上传覆盖云端确认 — 已定：上传前加二次确认」，但其 UI §3 又把上传归为「非破坏性（Spin + Toast）」—— **spec 内部矛盾**。本版本按作者最新决定**消解矛盾**：

- **上传（本地 → 云端）= 非破坏性**：覆盖的是云端备份副本，本地主数据不动 → 轻提示（Spin + success Toast），**不加 Modal**。
- **从云恢复（云端 → 本地）= 破坏性**：清空本地主数据 → `Modal type="warning"` + Checkbox 二次确认（复用 P1 LocalBackupSection 同款范式）。

## Premises

1. **加密数据密文迁移链路成立**（P1 已验证）：导出含 `cryptoMetadata.salt` + contexts 密文，导入方写同 salt → 用户输同主密码 → `deriveKey` 得同密钥 → 解密成功。云上传/下载只是把同一份导出 JSON 经对象存储搬运，链路不变。
2. **对象存储走 AK/SK 直传签名**，STS 临时凭证需自建后端超范围（伞形 spec 已排除）。
3. **AK/SK 经主密码加密存储**：配置/使用云前必须已解锁（`CryptoService.getEffectiveKey` 非空）。解锁态在 `chrome.storage.session` 生命周期内复用；service worker 重启不清空 session（仅浏览器完全关闭才清空）。
4. **SDK 浏览器可用**（D6 前提）：`ali-oss`、`cos-js-sdk-v5` 均支持浏览器环境并内部封装签名。⚠️ **此前提是本版本最大未知**，P2 第一步必须实测验证（见「前置条件」）；无手写回退，若 SDK 不达标需回头重开决策。

## 架构：策略模式（D5）

### Provider 策略接口（provider 无关，可扩展核心）

```ts
// src/services/cloud/types.ts
export type ProviderId = 'oss' | 'cos'; // 未来追加：| 'aws' | 'r2' | ...

/** 单个服务商的连接配置（明文，仅存在于内存/解锁态，不入盘）*/
export interface CloudStorageConfig {
  region: string;
  bucket: string;
  accessKeyId: string;
  accessKeySecret: string;
  endpoint?: string; // OSS 自定义域名 / COS 可选
}

/** 驱动 UI 表单动态渲染的字段定义 —— 新服务商声明字段即可，无需改 UI */
export interface ConfigFieldDef {
  name: keyof CloudStorageConfig;
  label: string;
  type: 'text' | 'password' | 'select';
  options?: string[]; // type='select' 时的候选（如 region 列表）
  required: boolean;
  placeholder?: string;
}

/** 每个云服务商的策略契约 */
export interface CloudStorageProvider {
  readonly id: ProviderId;
  readonly label: string; // '阿里云 OSS' / '腾讯云 COS'
  readonly configFields: ConfigFieldDef[];
  /** 测试连通性：以当前凭证能否访问 bucket；失败 throw */
  testConnection(config: CloudStorageConfig): Promise<void>;
  /** 上传备份（覆盖固定 key） */
  uploadBackup(config: CloudStorageConfig, blob: Blob): Promise<void>;
  /** 下载备份 */
  downloadBackup(config: CloudStorageConfig): Promise<Blob>;
}
```

可扩展性要点：**新服务商只需新增一个 `CloudStorageProvider` 实现并注册**，`configFields` 元数据让 UI 通用渲染其配置表单，不必写专属 UI 代码。

### 策略实现 + 注册表

```ts
// src/services/cloud/providers/OssProvider.ts  —— 内部用 ali-oss
// src/services/cloud/providers/CosProvider.ts  —— 内部用 cos-js-sdk-v5
// src/services/cloud/providers/index.ts
export const cloudProviders: Record<ProviderId, CloudStorageProvider> = {
  oss: new OssProvider(),
  cos: new CosProvider(),
};
export function getCloudProvider(id: ProviderId): CloudStorageProvider {
  return cloudProviders[id];
}
```

每个 Provider 内部用各自 SDK 实例化（`new OSS({...})` / `new COS({...})`），签名完全交给 SDK。「SDK vs 手写」是隔离在实现内部的细节，换实现不影响外部接口。

### CloudStorageService（凭证加密 + 编排，provider 无关）

```ts
// src/services/CloudStorageService.ts
const CREDS_KEY = (id: ProviderId) => `octane.cloudCreds.${id}`;
const LAST_BACKUP_KEY = (id: ProviderId) => `octane.lastBackupAt.${id}`;

// 凭证按 provider 分键存储（两 Tab 各配各的）
export async function saveCloudConfig(id, config) {
  // 要求已解锁
  const { encryptedData, iv } = await CryptoService.encrypt(JSON.stringify(config));
  await chrome.storage.local.set({ [CREDS_KEY(id)]: { encryptedData, iv, savedAt: Date.now() } });
}
export async function getCloudConfig(id): Promise<CloudStorageConfig | null> {
  // 要求已解锁；无配置返回 null
  const stored = await chrome.storage.local.get(CREDS_KEY(id));
  const raw = stored[CREDS_KEY(id)]; if (!raw) return null;
  return JSON.parse(await CryptoService.decrypt(raw.encryptedData, raw.iv));
}
export async function clearCloudConfig(id) {
  await chrome.storage.local.remove(CREDS_KEY(id));
}
export async function getLastBackupAt(id): Promise<number | null> { /* 读 LAST_BACKUP_KEY */ }
async function setLastBackupAt(id, ts) { /* 写 LAST_BACKUP_KEY */ }

// 编排：解密凭证 → 委托 provider 策略
export async function testConnection(id) {
  const cfg = await getCloudConfig(id); if (!cfg) throw new Error('未配置云存储');
  await getCloudProvider(id).testConnection(cfg);
}
export async function uploadBackup(id, blob) {
  const cfg = await getCloudConfig(id);
  await getCloudProvider(id).uploadBackup(cfg, blob);
  await setLastBackupAt(id, Date.now());
}
export async function downloadBackup(id): Promise<Blob> {
  const cfg = await getCloudConfig(id);
  return getCloudProvider(id).downloadBackup(cfg);
}
```

复用 `CryptoService.encrypt/decrypt`（base64 `{encryptedData, iv}`，需解锁）；`iv` 非秘密，与密文明文同存 storage（伞形 spec §5.1 已论证）。

## 数据模型

- **凭证存储**：`chrome.storage.local`，键 `octane.cloudCreds.{providerId}` → `{ encryptedData: string(base64), iv: string(base64), savedAt: number }`。AK/SK 密文落盘，不可读明文。
- **上次备份时间**：`chrome.storage.local`，键 `octane.lastBackupAt.{providerId}` → `number`（毫秒时间戳，非敏感，明文）。
- **备份对象 key**：固定 `octane/backup/octane-backup.json`（覆盖式单文件，无历史版本）。`src/services/cloud/constants.ts` 的 `BACKUP_OBJECT_KEY`。
- **导出/导入 JSON schema**：沿用 P1（`schema='octane-backup'`, `version=1`），云只是搬运同一份文件。

### ui-ux-pro-max 映射（UX 落地）

| 指南 | 落地 |
|---|---|
| form-labels（每输入必带可见 label，禁 placeholder-only） | `configFields` 元数据生成 `<label>`；SK 用 `mode="password"` |
| controlled components | value+onChange，表单态进 `useBackup`（per-provider） |
| confirmation dialogs（破坏性） | **仅从云恢复** → `Modal type="warning"` + Checkbox「我了解此操作不可撤销」勾选后才启用 danger 主按钮 |
| error feedback / error messages / error recovery | 失败 Toast `role="alert"`（aria-live）+ 按分类给可操作提示（CORS / AK-SK 权限） |
| loading-buttons / loading-indicators | 每个异步按钮 `loading` + 互斥禁用其他操作防并发；>300ms 显示 Spin |
| submit feedback / confirmation messages | 成功 Toast（含时间），绝静默成功 |
| input-types | SK = password 输入 |

### 关键交互

- **未解锁态**：整区 disabled + Banner(warning)「凭证由主密码加密，请先解锁」。解锁后启用。
- **上传备份（非破坏性，D7）**：点击 → 按钮 Spin + success Toast「已上传，<时间>」。覆盖云端现有备份，不加 Modal（用户可在文案中知晓会覆盖）。
- **从云恢复（破坏性，D7）**：下载 → `parseBackupFile` 校验 → `Modal type="warning"`（正文：将清除当前全部数据并替换为云端备份，不可撤销；含加密数据则需用导出端主密码解锁）+ Checkbox 二次确认 → 确认后 `sendMessage('octane:apply-import')`（复用 P1 事务）→ success Toast。
- **测试连接**：Spin → success Toast「连接成功，桶可访问」/ 失败 Toast（含原因）。
- **清除配置**：移除 `octane.cloudCreds.{id}` → Toast「已清除云配置」。

## 数据流

### 上传备份

```
blob = buildBackupBlob()                 // 从 useBackup.exportData 抽出，导出+上传共用
→ CloudStorageService.uploadBackup(id, blob)
→ getCloudProvider(id).uploadBackup(cfg, blob)  // SDK.put(BACKUP_OBJECT_KEY, blob) 覆盖
→ setLastBackupAt(id, now)
→ Toast.success（含时间）
```

### 从云恢复

```
blob = CloudStorageService.downloadBackup(id)  // SDK.get(BACKUP_OBJECT_KEY)
→ parseBackupFile(blob)                        // 复用 P1 校验（schema/version/字段/大小/cryptoMetadata）
→ 强确认 Modal（破坏性，D7）
→ browser.runtime.sendMessage({ type:'octane:apply-import', data })  // 复用 P1 覆盖事务
→ Toast.success + 提示「如含加密数据，请用导出端主密码解锁」
```

P1 导入事务（4 表 clear+put、cryptoMetadata 条件 put、syncContextMeta 重算、lock()、四表广播 + octane-import channel）对云恢复完全复用，不新增事务逻辑。

### 重构点（外科手术式）

- 从 `useBackup.exportData` 抽出 `buildBackupBlob()`（src/services/BackupService.ts），导出与上传共用。不改变现有导出行为。

## 前置条件（P2 第一步，硬门槛）

1. **CORS 通达性验证（第一道闸）**：用最小 PUT 验证扩展 origin 可达桶。被拦 → 文档化桶 CORS 配置（放行 `chrome-extension://<id>` 的 GET/PUT/HEAD）。未配通则云功能不可用，是用户侧前置条件。
2. **wxt.config.ts host_permissions**：加 `https://*.aliyuncs.com`、`https://*.myqcloud.com`。
3. **SDK 加载验证**：确认 `ali-oss` + `cos-js-sdk-v5` 在 WXT background service worker 可加载 + 量打包体积。⚠️ D6 选了无手写回退，此处是唯一确认点；若不达标需重开决策。
4. **TypeScript 类型**：`ali-oss` 无自带 d.ts → 安装 `@types/ali-oss`；`cos-js-sdk-v5` 自带类型。
5. **用户文档**：CORS 配置指南 + 建议最小权限子账号 AK/SK。

## 错误处理

Provider 方法 throw → `CloudStorageService` 透传 → `useBackup` 置 error → UI Toast（`role="alert`）按分类给可操作提示：

- 网络/CORS 错 →「连接失败：请检查桶 CORS 是否放行扩展 origin」
- 认证/签名错 →「认证失败：请检查 AK/SK 与桶权限」
- 未配置 →「请先配置云存储」
- 未解锁 → 配置区已 disabled + Banner 引导解锁

`testConnection` 失败同样分类提示，引导用户排查 CORS/AK-SK。

## Testing（Vitest）

- **OssProvider / CosProvider**：mock `ali-oss` / `cos-js-sdk-v5` 模块；断言 `put`/`get`/`testConnection`（HEAD 或 list）调用参数正确 + `BACKUP_OBJECT_KEY` 正确 + throw 路径。
- **CloudStorageService**：encrypt→save→load→decrypt 往返（test key）；`clearCloudConfig` 移除；未配置返回 null；未解锁抛错。
- **buildBackupBlob**：与 P1 `exportData` 输出结构一致。
- **useBackup 扩展**：upload/download/testConnection/save/clear 状态机转换（mock service）。
- **CloudBackupSection**：锁定/解锁渲染、恢复确认流程、configFields 动态渲染。
- **P1 复用**：`parseBackupFile` + `octane:apply-import` 的校验/事务已有测试覆盖恢复链路。

## Risks

- ⚠️ **D6 无手写回退**：若 `ali-oss` / `cos-js-sdk-v5` 在 WXT service worker 跑不通或打包体积不可接受，该 provider 会被卡住，需回头重开 D6（非自动回退）。缓解：P2 第一步 spike 实测先行，全量集成前确认。
- ⚠️ **CORS 是用户侧硬门槛**：桶未配 CORS 则云功能不可用；`testConnection` 给可操作错误，文档需写清配置步骤。
- **SDK 打包体积**：`ali-oss` + `cos-js-sdk-v5` 合计可能数百 KB；P2 第一步量体积，若炸则需评估代码分割（dynamic import 到 background）。

## Success Criteria

- 云配置保存后，AK/SK 在 `chrome.storage.local` 中为密文（不可读明文）；未解锁时无法获取凭证。
- `testConnection` 解锁后可签名连通（CORS 配通前提下）。
- 上传备份 → 从云恢复 → 5 表数据逐字段一致（含加密 context 可用原密码解锁）。
- 从云恢复是原子事务（复用 P1）：中途失败回滚，无半成品。
- 上传 = 轻提示；从云恢复 = 三重确认门槛（Modal + Checkbox + danger 按钮）。
- 所有异步操作有 loading + success/error 反馈；错误可访问（aria-live）。
- 策略模式可扩展：新增一个 provider 实现 + 注册即可接入，UI 通用渲染。

## Next Steps（建议分阶段实现）

- **P2**：CORS/SDK spike 验证 → `cloud/types.ts` + `constants.ts` → `OssProvider`/`CosProvider` + 注册表 → `CloudStorageService`（凭证层 + 编排）→ wxt host_permissions + `@types/ali-oss` → `CloudBackupSection` 配置 UI + 测试连接 → Vitest。验证：AK/SK 密文落盘、解锁后连通、桶 CORS 放行。
- **P3**：抽 `buildBackupBlob()` → `uploadBackup` + 上次备份时间 → `downloadBackup` + 从云恢复（复用 P1 导入）→ 恢复破坏性确认 → Vitest。验证：上传→恢复数据一致。

## 与伞形 spec 的关系

- **沿用**：D1/D2/D3、加密迁移链路、覆盖式语义、5 表数据范围、导入事务编排、Semi UI 主题、UI 组件选型。
- **精化/新增**：D4（双 provider）、D5（策略模式架构）、D6（双 SDK 无回退）、D7（上传轻提示，反转 OQ#4）、D8（清除配置入口）。
- **消解矛盾**：伞形 spec OQ#4 与其 UI §3 关于「上传是否需确认」的内部矛盾，本版本按 D7 统一为「上传轻提示、恢复强确认」。
