# 快速解锁 PIN 与统一自动锁定(信封机制)

用户反馈主密码日常解锁繁琐(≥12 字符、浏览器重启即需重输),希望支持 4/6 位短 PIN 与可配置过期时间。我们采用双层解锁模型:主密码强度下限不放宽,仍是唯一加密根;新增可选「快速解锁 PIN」(4 位数字 / 6 位数字 / ≥4 位自定义),PIN 经 PBKDF2-SHA256(600,000 迭代、独立随机盐)派生 KEK,把派生密钥包装成「PIN 信封」。锁定模型统一为单一「自动锁定」设置(页面不可见持续 X 后锁定;档位:立即 / 1 / 5 / 15 / 60 分钟 / 永不,默认永不;home 与 sidepanel 共用),外加 PIN 区内子开关「重启浏览器后仍可用 PIN 解锁」(默认关;开启后信封才持久化到 chrome.storage.local,否则仅存 session)。

## Considered Options

- **允许把主密码本身设为 4 位数字(单层放宽)**:加密强度直接暴露在 1 万种组合的暴力破解下,且无回退路径——拒绝。
- **「重启后完全免输」(明文持久化派生密钥)**:等于放弃加密,Bitwarden 对同类的 Never 档同样强烈劝退——拒绝。
- **保留 sidepanel 的 hardCap(最长解锁时长)**:与「锁得更少」的产品方向冲突,其防护场景与闲置锁定重叠——移除,仅做存量迁移。

## Consequences

- 开启「重启保持」后,能读到本地存储的攻击者可离线暴力破解信封(4 位 PIN 仅 1 万种组合,KDF 迭代成本是唯一屏障)。这是知情选择的固有风险,与 Bitwarden BFU 模式相同;设置 UI 以警示文案明示,不替用户做决定。
- 连续 5 次 PIN 输错熔断:擦除信封、关闭 PIN、回退主密码;失败计数持久化到 local,刷新不可重置,成功解锁即清零。
- 修改主密码或关闭 PIN 时必须擦除并重建信封;PIN 的设置 / 修改 / 关闭均以主密码确认为前置门槛,防止解锁状态下被劫持。
- `docs/PRIVACY.md` 中「派生密钥仅存会话存储」的承诺需随实现同步修订(如实披露信封持久化选项)。
- 存量迁移:sidepanel 的 grace 值归入最近档位,hardCap 废弃,`octane-ttl-config` 旧键读取迁移后删除。
