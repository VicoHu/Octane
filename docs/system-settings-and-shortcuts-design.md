## Problem Statement

两个相互关联的需求：

1. **系统设置模态窗**：在 Sidebar 的「设置」Dropdown 里增加「系统设置」入口，点击弹出模态窗。模态窗左侧是分类 menu，右侧是对应设置详情页。借此把现有零散的设置（主密码、数据备份和同步）与新增的快捷键设置，统一收敛进一个设置中心。
2. **全局快捷键设置**：在系统设置模态窗里增加「快捷键」分类，提供「打开 Home 页面 / 打开 Popup 弹窗 / 打开 Side Panel」三类快捷键，且对浏览器所有 tab 页全局生效。

## What Makes This Cool

Octane 当前所有功能都要点图标或翻 Sidebar。给三个核心入口（首页、侧栏、弹窗）配上全局快捷键，是从「鼠标驱动」到「键盘驱动」的体验跃迁——重度用户双手不离键盘就能在任意网页一键召唤 Octane。配套的统一设置中心则让设置项第一次有了「正经的家」。

## Constraints

- **平台：Chrome MV3**（WXT + React + Semi Design）。当前仅专注 Chrome，不做 Firefox 适配。
- **现有架构约束**：
  - Home 通过 `focusOrCreateHomeTab()`（tabs API）打开/聚焦。
  - Side Panel 通过 `chrome.sidePanel` API，`background.ts:70` 已设 `openPanelOnActionClick: true`（左击图标直达 side panel）。
  - manifest 同时声明了 `default_popup: popup.html` 和 `side_panel.default_path: sidepanel.html`。
- **UI 规范**：使用 Semi Design 组件库；深色 token 需在 `.semi-always-dark` scope（见 [docs/semi-design-spec.md](semi-design-spec.md)）；Portal 弹层须 `getPopupContainer` 锚定 sidebar-container 防变亮色。

## Premises（已与用户确认）

> ⚠️ 这两个前提是整个方案的基石，源自 Chrome 平台硬限制，不是 Octane 的选择。

**前提一：Chrome MV3 扩展无法在运行时编程修改快捷键按键绑定。**
快捷键只能在 manifest `commands` 里声明；按键值由用户去 `chrome://extensions/shortcuts` 自行设定，扩展代码无写入 API（`chrome.commands` 只能读 `getAll()`，不能改）。所以「在设置页里录键自定义」这套交互在 Chrome 扩展里做不到。**设置页的「快捷键」分类只能是只读展示当前绑定 + 跳转 shortcuts 页让用户改。** （D1 已确认）

**前提二：popup.html 在当前架构里是「死入口」。**
由于 `openPanelOnActionClick: true`，左击图标开 side panel、`default_popup` 被忽略；唯一能触发 popup 的 `_execute_action` 快捷键在该模式下也被 Chrome 转去开 side panel。故 popup 当前对用户不可达。强行做「快捷键打开 popup」会与 side panel 抢 action 行为，让本次需求从「加设置窗」膨胀为「重设计 action 形态」。**本期只做 Home + Side Panel 两个快捷键，popup 死入口单独立 issue 处理。** （D2 已确认）

**前提三：设置中心做成「统一设置中心」而非最小化。**
menu 含「快捷键 / 数据备份和同步 / 主密码」三项；Sidebar Dropdown 简化为单一「系统设置」入口。比最小方案更整齐，代价是需迁移 Sidebar 既有逻辑与测试。用户在 D3 主动选择了这个更完整的方案，接受随之而来的改动面。

## Approaches Considered

### Approach A: Semi Modal + 左 Nav 右详情（统一设置中心）✅ 已选
- **承载**：Semi `Modal`（`size="large"`，宽 ~720px），内部分左右两栏。左栏用 Semi `Nav`（`type="line"` vertical）或 vertical `Tabs` 做分类 menu；右栏按选中项渲染对应详情组件。
- **menu 三项**：快捷键 / 数据备份和同步 / 主密码。
- **入口**：Sidebar Dropdown 由「主密码 / 修改主密码 / 数据备份和同步」简化为单一「系统设置」项，点击开 Modal。
- **Effort**: M；**Risk**: Low（全用 Semi 既有组件，Modal 已大量使用）。

### Approach B: SideSheet 承载
现有「数据备份和同步」已用 `SideSheet`。但用户明确要「模态窗」，且备份内容较丰富、SideSheet 偏窄不适合左 menu 右详情。**否决**。

### Approach C: 独立 settings.html entrypoint
单独全屏设置页，路由式。功能最强但远超「模态窗」需求，需新增 entrypoint + 路由 + 打开方式设计。**否决**（YAGNI）。

## Recommended Approach

**Approach A：Semi Modal 统一设置中心。**

理由：贴合用户「模态窗 + 左 menu 右详情」表述；Semi Modal/Nav 是项目既有模式，零新依赖；把零散设置收敛成一处，符合 D3 的统一中心决策。

### 快捷键实现细节

**manifest（`wxt.config.ts` → `manifest.commands`）：**
```ts
commands: {
  'open-home': {
    suggested_key: { default: 'Alt+Shift+H' },
    description: '打开 Octane 首页',
  },
  'open-sidepanel': {
    suggested_key: { default: 'Alt+Shift+S' },
    description: '打开 Octane 侧边栏',
  },
},
// 不声明 minimum_chrome_version：sidePanel API 本身隐含版本要求（114+），
// 两个命令均用普通命令名，无 Chrome 116+ 保留命令硬依赖（Eng Review A2 决议）。
```
- 两个命令都用**普通命令名**（非保留命令），统一在 background `onCommand` handler 处理，可单测、无版本硬依赖（Eng Review A2 决议，outside voice P0 确认）。
- `suggested_key` 仅为建议；冲突时 Chrome 让用户在 shortcuts 页自行解决。

**background（`background.ts`，Eng Review A1 决议：onCommand listener 顶层注册，与 onMessage/onInstalled 同级，避免 SW 唤醒时序丢首次按键）：**
```ts
// 顶层注册（与现有 onMessage/onInstalled listener 同策略）
browser.commands.onCommand.addListener((command) => {
  if (command === 'open-home') {
    focusOrCreateHomeTab().catch((e) =>
      console.error('[octane] 快捷键唤起 home 失败', e),
    );
  } else if (command === 'open-sidepanel') {
    // sidePanel.open 需 tabId：取当前激活 tab；无 active tab（devtools 聚焦等）
    // 则仅记日志退出，不 fallback（outside voice P1，无更好降级）。
    chrome.tabs.query({ active: true, lastFocusedWindow: true }).then(([tab]) => {
      if (!tab?.id) {
        console.error('[octane] 打开 side panel 失败：无 active tab');
        return;
      }
      chrome.sidePanel.open({ tabId: tab.id }).catch((e) =>
        console.error('[octane] 打开 side panel 失败', e),
      );
    });
  }
});
```

**快捷键设置分区（`ShortcutsSection.tsx`）：**
- `chrome.commands.getAll()` 读取两个命令当前绑定（异步，`useEffect` + `useState`）。
- 只读列表：命令描述 / 当前按键（未设置则显示「未设置 − 前往 chrome://extensions/shortcuts 配置」）。
- 「前往自定义」按钮 → `chrome.tabs.create({ url: 'chrome://extensions/shortcuts' })`。
- 顶部说明 Banner：「Chrome 规定扩展不能直接修改快捷键，请点击下方按钮在浏览器设置页自定义按键。」

## 实施期 Bug 修复（2026-06-28，TDD 编码后实测）

实测发现三处与 plan 评审的偏差，已修复：

1. **side panel 快捷键（反转 plan-eng-review A2）**：A2 原定「普通命令 `open-sidepanel` + handler 调 `chrome.sidePanel.open({tabId})`」。实测报错 `sidePanel.open() may only be called in response to a user gesture` — Chrome 的 commands `onCommand` **不**被视为 user gesture。**反转为保留命令 `_execute_side_panel_action`（Chrome 116+，由 Chrome 直接打开 side panel，不经 handler）+ `minimum_chrome_version: '116'`**。home 保持普通命令 `open-home` + handler（tabs API 无需 gesture）。`CommandHandler` 删 sidepanel 分支。
2. **UnlockModal z-index**：UnlockModal 是自定义 overlay（`z-index:1000`），与 Semi Modal(1000) 同层 + App 级挂载早 → 嵌套在 SettingsModal 内触发时被压下。修：overlay `z-index: 1000 → 1100`。
3. **Modal 底部 padding**：Semi Modal body 默认 `padding:0`（间距靠区域 marginY），`footer=null` 时底部内容贴边。修：`bodyStyle: paddingBottom = var(--space-xl)`（项目 token；**Semi 不暴露 spacing CSS var**，编译为静态值，必须用项目 `--space-*`，非 `--semi-spacing-*`）。
